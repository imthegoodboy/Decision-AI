1. Introduction

People increasingly ask AI assistants to help them decide: which phone to buy, which university to attend, which insurer to trust. Web-enabled assistants answer fluently and attach citations, which makes their answers look checkable. They often are not. In a human audit of four generative search engines, only 51.5% of generated sentences were fully supported by their citations, and citation precision was inversely correlated with how useful the answers were judged to be [1]. Retrieval also opens an attack surface: a handful of planted documents can steer retrieval-augmented systems toward attacker-chosen answers [14, 15]. For everyday decisions, the result is persuasive advice whose evidential basis the user cannot cheaply inspect, and that a motivated actor can manipulate by publishing one convincing page.

Track 2 of the sprint asks a direct question: when an AI system uses a reliability or provenance tool, does its behaviour and accuracy actually improve? We study this question in the setting where it matters to ordinary users: end-to-end decision support from live web sources. We built Decision AI, a decision-support agent whose recommendations are assembled only from claims that have been bound to a verbatim quote in a fetched page, checked against that passage, cross-checked against the other sources, and logged in a tamper-evident record. We then ran a controlled experiment on {{N_QUESTIONS}} real decision questions in which every system sees identical evidence, with and without a planted, credible-looking false source.

Our main contributions are:

  1. An open, claim-level verification and provenance layer for web-researching agents: verbatim quote binding, deterministic quote location, hybrid passage retrieval, an entailment judge with cross-source corroboration and contradiction detection, a two-part source reliability score (metadata prior plus a track record earned through verification), and a SHA-256 hash-chained audit log that seals each research dossier. Its outputs are structured so that both people and other AI systems can consume them.
  2. A controlled measurement of whether the layer changes agent behaviour ({{N_QUESTIONS}} decisions × 3 systems × 2 conditions), including an ablation that gives the baseline the same instructions as a prompt, isolating the effect of the infrastructure from the effect of asking the model to be careful.
  3. Evidence on which reliability signals are hard to game. A planted page with fabricated publisher, author and recent date scores well on metadata alone; we measure how much of that advantage survives once reliability must be earned through corroboration.
  4. A reusable evaluation harness and dataset: questions, cached source pools with content hashes, planted articles with their ground-truth false claims, all system outputs, judge decisions and a human-audit sample.

3. Methods

3.1 Decision AI: claim-level verification and provenance

Decision AI converts a conversation into a structured decision profile (goal, budget, region, must-haves and weighted priorities), then runs the pipeline in Figure 1. Steps drawn with dashed borders are deterministic code; the others call a language model through a strict JSON schema.

Verification rules. A claim the judge marks supported but whose quote cannot be located in the page is downgraded to partial; a claim that conflicts with another source and is corroborated by none is marked contradicted. These rules are fixed in code and unit tested, so the model cannot talk its way past them.

Two-part reliability. Each source starts at 50 and receives transparent metadata signals: HTTPS (+3), named publisher (+4), named author (+5), publication date (+4) and recency within the decision's freshness window (+5, or −10 if stale), source kind (from +14 for government to −8 for forums), and depth (thin pages −8). These signals are cheap to fake. After verification the source earns +3 per claim corroborated by an independent source (max +12), −8 per contradicted claim (max −24) and −3 per unsupported claim (max −10). Every signal is shown to the user.

Ranking and provenance. Ranking is a weighted sum of criterion scores in which unevidenced cells are imputed at a neutral 5 and flagged; option confidence is 0.35·coverage + 0.30·support rate + 0.20·reliability + 0.15·freshness − a contradiction penalty. Moving a priority slider re-ranks options instantly in the browser using the same code. Every step (queries, retrieved URLs with content hashes, each claim verdict, contradictions, weight changes) is appended to a per-decision audit log in which each event's hash is SHA-256 over the previous hash, sequence number, type, canonical JSON payload and timestamp, in the spirit of secure audit logs and Certificate Transparency [21, 22]. When a run finishes, the SHA-256 of the full dossier is committed to the chain, so later edits to stored evidence are detectable.

3.2 Experimental design

Questions. We wrote {{N_QUESTIONS}} realistic decision questions across six domains (consumer technology, education and careers, personal finance, health and wellbeing products, home and mobility, software and services; five each), situated in India, the US, the UK, Germany or globally, each stating the user's constraints (e.g. budget, region, priorities).

Shared evidence. For each question, the planner wrote up to {{QUERIES}} search queries; pages were found with the OpenAI Responses API web-search tool and fetched and extracted by our own code. The first {{POOL_SIZE}} readable pages (≥150 words) formed the question's source pool, each truncated to {{CHAR_BUDGET}} characters. All systems receive exactly the same numbered source texts, so differences cannot come from retrieval.

Planted source. For the poisoned condition, a model (gpt-5.5) wrote, from the genuine sources, a 600–850-word article in the style of an independent buying guide containing exactly three specific, plausible, decision-relevant false claims that contradict the genuine sources, with a fictional publisher, a named author and a publication date 5–45 days old. The planted article was inserted at a deterministic, non-first position in the pool. It was never published.

Systems. All three systems generate with the same model ({{FAST_MODEL}}). Baseline RAG receives the sources and is asked for a recommendation with inline [n] citations. Self-check receives the same prompt plus explicit instructions to verify every statement against the cited source, to flag disagreements between sources and say which is more credible, and to be sceptical of single-source claims; it tests whether asking for verification achieves what the infrastructure does. Decision AI runs the verification core (steps 3–12) on the same pool and renders its dossier with the same citation convention.

3.3 Measures

An independent judge ({{JUDGE_MODEL}}, a different and larger model than the systems') evaluated every answer identically. It (J1) decomposed the answer into atomic factual claims with their citations, extracted the recommended option and whether the answer discloses conflicting evidence; (J2) labelled each cited claim supported, partial or unsupported against the top three BM25 passages of each cited source, and each uncited claim against the top five passages in the whole pool; and (J3), in the poisoned condition, labelled each of the three planted false claims as asserted, flagged as disputed, or absent. From these we compute: citation support (share of cited claims fully supported), unsupported statements (share of all factual claims not supported, cited or not), conflict disclosure, planted adoption (answers asserting ≥1 planted falsehood), planted source citation, recommendation flips between clean and poisoned conditions, and cost (tokens, calls, latency). {{HUMAN_AUDIT_METHOD}}

Statistics. The design is paired by question. We report means with 95% percentile bootstrap confidence intervals over questions (10,000 resamples), Wilcoxon signed-rank tests for paired continuous metrics and exact McNemar tests for paired binary outcomes.
