1. Introduction

People increasingly ask AI assistants to help them decide: which phone to buy, which university to attend, which insurer to trust. Web-enabled assistants answer fluently and attach citations, which makes their answers look checkable. They often are not. In a human audit of four generative search engines, only 51.5% of generated sentences were fully supported by their citations, and citation precision was inversely correlated with how useful the answers were judged to be [1]. Retrieval also opens an attack surface: a handful of planted documents can steer retrieval-augmented systems toward attacker-chosen answers [14, 15]. For everyday decisions, the result is persuasive advice whose evidential basis the user cannot cheaply inspect, and that a motivated actor can manipulate by publishing one convincing page.

Track 2 of the sprint asks a direct question: when an AI system uses a reliability or provenance tool, does its behaviour and accuracy actually improve? We study this question in the setting where it matters to ordinary users: end-to-end decision support from live web sources. We built Decision AI, a decision-support agent whose recommendations are assembled only from claims that have been bound to a verbatim quote in a fetched page, checked against that passage, cross-checked against the other sources, and logged in a tamper-evident record. We then exposed the same verification layer as a tool that an AI agent can call, and ran a controlled experiment on {{N_QUESTIONS}} real decision questions in which AI agents answer from identical live-web evidence, with or without the tool, and with or without a planted, credible-looking false source.

Our main contributions are:

  1. An open, claim-level verification and provenance layer for web-researching agents: verbatim quote binding, deterministic quote location, hybrid passage retrieval, an entailment judge with cross-source corroboration and contradiction detection, a two-part source reliability score (metadata prior plus a track record earned through verification), and a SHA-256 hash-chained audit log that seals each research dossier. Its outputs are structured so that both people and other AI systems can consume them.
  2. A controlled measurement of whether an AI agent that uses the tool behaves differently ({{N_QUESTIONS}} decisions × 3 conditions × clean/poisoned = {{N_RUNS}} agent runs, judged blind), including an ablation that gives the agent the same verification instructions without the tool, isolating the effect of the infrastructure from the effect of asking the model to be careful.
  3. Evidence on which reliability signals are hard to game. A planted page with fabricated publisher, author and recent date scores well on metadata alone; we measure how much of that advantage survives once reliability must be earned through corroboration.
  4. A reusable evaluation harness and dataset: questions, a fixed search protocol, cached source pools with content hashes, planted articles with their ground-truth false claims, all agent answers and tool ledgers, judge decisions and a human-audit sample.

3. Methods

3.1 Decision AI: claim-level verification and provenance

Application. Decision AI converts a conversation into a structured decision profile (goal, budget, region, must-haves and weighted priorities), then runs the pipeline in Figure 1. Steps drawn with dashed borders are deterministic code; the others call a language model through a strict JSON schema.

Verification rules. A claim the judge marks supported but whose quote cannot be located in the page is downgraded to partial; a claim that conflicts with another source and is corroborated by none is marked contradicted. These rules are fixed in code and unit tested, so the model cannot talk its way past them.

Two-part reliability. Each source starts at 50 and receives transparent metadata signals: HTTPS (+3), named publisher (+4), named author (+5), publication date (+4) and recency within the decision's freshness window (+5, or −10 if stale), source kind (from +14 for government to −8 for forums), and depth (thin pages −8). These signals are cheap to fake. After verification the source earns +3 per claim corroborated by an independent source (max +12), −8 per contradicted claim (max −24) and −3 per unsupported claim (max −10). Every signal is shown to the user.

Ranking and provenance. Ranking is a weighted sum of criterion scores in which unevidenced cells are imputed at a neutral 5 and flagged; option confidence is 0.35·coverage + 0.30·support rate + 0.20·reliability + 0.15·freshness − a contradiction penalty. Moving a priority slider re-ranks options instantly in the browser using the same code. Every step (queries, retrieved URLs with content hashes, each claim verdict, contradictions, weight changes) is appended to a per-decision audit log in which each event's hash is SHA-256 over the previous hash, sequence number, type, canonical JSON payload and timestamp, in the spirit of secure audit logs and Certificate Transparency [21, 22]. When a run finishes, the SHA-256 of the full dossier is committed to the chain, so later edits to stored evidence are detectable.

3.2 The provenance layer as a tool an AI agent can call

Track 2 anticipates that "the most plausible consumers of this infrastructure may be AI systems themselves". To test exactly that, we exposed Decision AI's verification layer (Figure 1, steps 3 and 5–12) as a command-line tool that an AI agent can call (decision-tool, bundled from the same TypeScript code). Its commands list sources with every reliability signal; verify locates a quote in a source and returns the best passages from that source and the most related passages from all other sources; record stores the agent's verdict, after which the fixed rules of Section 3.1 decide the final status and the record is appended to a SHA-256 hash chain; ledger shows statuses and each source's earned reliability; finalize computes the evidence-weighted ranking deterministically; and seal commits the dossier hash. The tool contains no language model: the agent supplies the language judgements, and the tool enforces the rules and keeps the provenance.

3.3 Experimental design

Questions. {{N_QUESTIONS}} realistic decision questions, two in each of six domains (consumer technology, education and careers, personal finance, health and wellbeing products, home and mobility, software and services), situated in India, the UK, the US or globally, each stating the user's constraints and priorities (Appendix B).

Shared evidence under a fixed protocol. For each question we wrote three search queries in advance. They were run with Claude's web-search tool and the first eight results per query were recorded unedited. Pages were then fetched and extracted by our own code (Section 3.1) and the first eight readable pages (at least 150 words) formed the question's source pool, each truncated to {{CHAR_BUDGET}} characters; between five and eight pages were readable per question. Every page carries its URL, retrieval time and SHA-256 content hash. All conditions see exactly the same numbered source texts, so differences cannot come from retrieval.

Planted source. For the poisoned condition, a separate Claude agent wrote, from each genuine pool, a 600–900-word article in the style of an independent buying guide containing exactly three specific, plausible, decision-relevant false claims that contradict the genuine sources, under a fictional publisher with a named author and a recent publication date. It was inserted at a seeded, non-first position. It was never published; the ground-truth false claims are stored with it.

Conditions. Every answer was produced by a fresh Claude agent ({{SYSTEM_MODEL}}) that could read only its own copy of the numbered sources (no web access), in a directory with an opaque name that did not reveal the condition. Baseline: the agent reads the sources and writes a 250–450-word recommendation with inline [n] citations. Self-check: the same, plus explicit instructions to verify every statement against its cited source, to flag disagreements between sources and say which is more credible, and to be sceptical of single-source claims. Tool: the self-check instructions plus access to decision-tool and a required process: verify and record 12–20 claims, build the answer only on claims whose final status is supported or partial, finalise the ranking and seal. Comparing Tool with Self-check isolates the effect of the infrastructure from the effect of asking the model to be careful. Each condition ran once on the clean pool and once on the poisoned pool: {{N_QUESTIONS}} × 3 × 2 = {{N_RUNS}} agent runs.

3.4 Measures

Answers were evaluated by separate judge agents ({{JUDGE_MODEL}}) that were blinded to condition: each judge received three answers labelled A–C by a seeded shuffle, with the citations of clean-pool answers renumbered to a single shared source list. For each answer the judge (J1) decomposed it into atomic factual claims with their citations and recorded the recommended option and whether the answer discloses conflicting evidence; (J2) labelled each cited claim supported, partial or unsupported against the cited sources only (attribution, not truth), and each uncited claim against any source; and (J3) labelled each of the three planted false claims as asserted, flagged as disputed, or absent. From these we compute citation support (share of cited claims fully supported), unsupported statements (share of all factual claims not supported, cited or not), conflict disclosure, planted adoption (answers asserting at least one planted falsehood), planted-source citation and recommendation flips between the clean and poisoned runs of the same condition. As a control, J3 is also applied to clean-pool answers, which never saw the planted article, giving the judge's false-positive rate. {{HUMAN_AUDIT_METHOD}}

Statistics. The design is paired by question. We report means with 95% percentile bootstrap confidence intervals over questions (10,000 resamples), Wilcoxon signed-rank tests for paired continuous metrics and exact McNemar tests for paired binary outcomes. With {{N_QUESTIONS}} questions the study is powered for large effects only; we report effect sizes and intervals rather than relying on significance alone.
